# Publication path after the hardware regression

The original experiments can remain scientifically useful. A known implementation mismatch must be described as part of the executed method and its limitations; it cannot be silently replaced in the methods by corrected code while keeping the old results. Acceptance cannot be guaranteed. The existing review explicitly supports a narrowly scoped embedded-control feasibility study and requires more evidence for architecture-specific or general robustness claims.

## Recommended scope

Keep the original hardware-proven August policy as the main embedded feasibility artifact. Describe A/B/C as the particular trained and selected controllers evaluated on this robot. State that C performed better in those recorded trials. Do not infer that recurrence caused the difference: training/deployment mismatch affected the feedforward policies differently, actor capacity differed, and training budgets/selection were not a controlled architecture experiment.

Present r2 and the seed-43 C/D development pilot as separate correction/replication experiments. Include the failed C standing attempt. Its commands were zero; it never reached the automatic testbench; it fell 5.336 s after rearm. This is a standing failure, not a completed 11-stage test and not a zero-fall record just because the testbench counter remained zero. Use falls, exposure and coverage before alive-masked tracking/attitude statistics. Preserve C42 and every other seed. No post-hoc outlier exclusion based on unfavorable performance.

The earlier recovered GRU and the first timing adaptation inherit the original seed-42 weights. The second timing adaptation inherits the fresh pilot's seed-43 weights. Neither adaptation is a new independent training replicate. Record the parent checkpoint and extra updates explicitly; do not compare adapted C against unadapted D as a controlled recurrence ablation.

## Changes mapped to the supplied review and manuscript

1. **III-E actuator model / Table 5 / supplement S4:** give the executed August 15 ms update law. Its 5–10 ms lag parameter was ineffective. Remove any claim that its randomization introduced a dynamic time constant. Distinguish command transport, sensor age and current-response filtering. The observed two-tick command-to-reported-current delay includes feedback age and cannot be assigned entirely to torque onset.
2. **III-A, III-G and Fig. 2:** define network command, post-model effective current and measured current separately. August training used post-model current features; deployed firmware used the previous logical command. The October correction changed their value but still delayed the entire vector in half the episodes, introducing an extra history tick. The new sensor-only mode corrects that latter discrepancy. Report both historical mismatches rather than rewriting the August interface as exact parity.
3. **III-E / S6 motor measurements:** the stopping-edge static deadzone is a surrogate, not a hysteresis model. Free-running sweep data do not identify loaded torque gain. The 0.0007 damping value is a free-run-derived estimate, not a direct measurement of loaded wheel/ground damping. Do not present that modeling revision as established physical truth or claim it alone caused the regression.
4. **II-A/B and III-A/C/G frames/falls:** use the inspected firmware's axes, signs, world yaw-rate formula, wheel-current mapping and 15 ms rate. State the simulated tilt rule separately from firmware's latched approximately 34.4-degree pitch cutoff and approximately 5-degree rearm threshold. Do not replace either by an unexecuted contact-fall specification.
5. **III-C reward:** report historical reference back-calculation ordering, the ineffective/negligible excess-position term, and the historical hold reference. Describe the corrected hold reference only for runs that used it. No retrospective method substitution.
6. **IV-A / Table 7 / supplement S7:** either label RMS of mean absolute wheel current precisely or consistently recompute pooled two-wheel RMS. Define drift with an explicit origin, reset rule, interval and signed/absolute convention. Stage SD is variation between stages, not uncertainty over independently repeated trials.
7. **III-D/F/G, V-B and Tables 4–6:** bind each reported policy to training revision, resolved config, actually applied parameter ranges, cumulative updates, checkpoint-selection rule, exact exported model SHA256 and capture/build provenance. Keep source-commit identity separate from proof of the flashed binary. The new C output replay agrees with the intended ONNX to 7.2e-7 A on the supplied active trace; that verifies inference, not motor torque calibration.
8. **IV-F / supplement S8/S9:** replace provisional simulation numbers only with recovered, versioned raw outputs. State their source/evaluation seeds, number of environments, duration, resets, coverage and masks. Separate fixed-budget finals from validation-selected exports. Preserve original raw tables and version replacement tables explicitly.
9. **Discussion/conclusion:** the corrected fresh policy's excellent simulation standing did not predict transfer. The current evidence supports a deployment and reproducibility case study, not a general memory advantage or proof that more faithful simulation necessarily improves transfer.

## Proposed discussion paragraph

An implementation audit identified differences between the training actuator/observation pipeline and the deployed controller. The original hardware results therefore characterize the archived controller produced by that pipeline, rather than an idealized implementation of the corrected method. A subsequent fresh seed-43 recurrent development pilot passed its simulator selection procedure but failed an unforced physical standing attempt before the automatic testbench began. Numerical replay reproduced its embedded network outputs, while additional simulation diagnostics exposed sensitivity to the timing of previous-command feedback. These findings show that successful numerical deployment and favorable simulation scores were insufficient to establish physical robustness. The corrected pilot, the original deployment, and later warm-start recovery experiments are reported separately; no failed seed or trial is excluded.

## Smallest useful additional hardware dataset

Use the same firmware source, sensor calibration, gains, stance, battery condition and surface. First repeat short zero-command standing trials with the old hashed reference and any qualified recovery candidate, alternating order and recording every attempt including failures. If basic standing succeeds consistently, run the same automatic protocol with equal repetitions. Log rearm, model hash, commands, raw observations, logical current commands, physical current feedback and age/timing. Manual release time and any interventions need event markers or an accompanying timed video; rearm time alone is not release time. Report per-trial outcomes and distributions, then per-stage metrics with coverage.

The original A/B/C archive remains evidence even if the new candidate fails. A new successful hardware run is required before claiming that the regression has been fixed physically. The one failed C capture cannot rank C against D because D has no matched capture here.

## Outcome of the bounded recovery work

Neither adaptation qualified. The original-weight adaptation failed tracking; the pilot-weight adaptation passed the standard simulator gates but did not meet the predeclared reduction in fast current changes. Both remained upright in the simulator, and neither was tested physically. Include this as an unresolved transfer limitation, not a recovered-hardware result. Full per-scenario results, coverage and the failed acceptance conditions are in `RESULTS.md`.

For immediate continuation, keep the original verified hardware artifact and source revision for the paper's existing experiment. If additional measurements are collected, use that same archived implementation and label it accordingly. Do not present its results as evidence for the newly corrected implementation. Controlled repeats of the existing original/recovered references can strengthen the hardware evidence; no new qualified recovery model is supplied here.
